2차 시도(재실행)에서 발견된 기능 결함 보고다. 이 과제를 다시 수행해 결함을 고쳐라.

[사용자 제보]
"한강시 게임은 캐릭터가 이동하지 못함. (점프와 마우스 이외의 컨트롤은 거의 안됨.)"

[재현 — 실제 브라우저 키보드 이벤트]
이 저장소에서 배포된 hangang-city.html 을 브라우저로 열면, 알파벳 키가 전혀 먹지 않는다.
점프(Space)와 마우스 시점만 동작한다. 이동·주행·승하차·수배·은폐가 모두 불가능하다.

측정 결과 (0.5초 입력 후 캐릭터 이동 거리):

  W   (e.code='KeyW')      이동 거리 0.000   ← 동작 안 함
  A   (e.code='KeyA')      이동 거리 0.000   ← 동작 안 함
  D   (e.code='KeyD')      이동 거리 0.000   ← 동작 안 함
  Shift (e.code='ShiftLeft') 이동 거리 0.009  ← 동작 안 함
  ArrowUp (e.code='ArrowUp') 이동 거리 1.598  ← 동작함
  Space  (e.code='Space')   점프 동작          ← 동작함

[원인 — 이미 좁혀둔 지점]
키 입력 정규화 함수가 브라우저가 실제로 보내는 e.code 값을 처리하지 못한다.

  입력 바인딩:  setKey(e.code || e.key, true)
  정규화:      normalizeCode(c) → 소문자 변환 후 'space'/'shift'/'ctrl'/'arrow'만 특별 처리
  매핑표:      KEY_ACTIONS = { 'w':'fwd', 'a':'left', 'd':'right', 's':'back', ... }

브라우저는 알파벳 키에 e.code='KeyW' 같은 값을 준다.
normalizeCode('KeyW') 는 'keyw' 를 돌려주고 KEY_ACTIONS 에는 'w' 만 있다.
setKey 는 e.code 가 항상 truthy 이므로 e.key 폴백('w')에 도달하지 못하고,
KEY_ACTIONS['keyw'] 가 undefined 라서 setKey 가 조용히 return 한다.
결과적으로 방향키·Space·Shift 만 동작한다.

[요구 사항]
1. 실제 브라우저 키보드 이벤트로 W/A/S/D 가 캐릭터를 이동시킬 것.
   e.code 를 쓰는 입력 경로와 e.key 를 쓰는 입력 경로 모두에서 동작해야 한다.
2. Shift(달리기), F(승하차·하차), E(수배), R(은폐), C(카메라), M(임무 패널) 도
   실제 키보드 이벤트에서 동작할 것. 방향키도 계속 동작할 것.
3. 키 반복(keydown 의 e.repeat) 처리와 브라우저 기본 동작(페이지 스크롤 등) 방지를
   깨뜨리지 말 것.
4. CharacterEvent 의 code·key·location 값에 의존하지 말고, 사용자가 실제로 누르는
   물리 키 기준으로 판정할 것. 키보드 배치(QWERTY/AZERTY/Dvorak)를 무시하고
   code 값을 기준으로 삼는 편이 안전하다.
5. 이 과제에 앞서 만든 다른 기능(미션 3종, 수배 1~3, 낮/노을/밤, 미니맵, 속도계,
   차량 주행·드리프트, 시드 기반 도시 생성)은 유지하거나 개선할 것.
6. hangang-city.html 은 계속 단일 HTML 파일이어야 한다. three.js 등 외부 에셋은
   쓰지 않는다.
7. 수정 후 헤드리스 Chrome으로 실제 KeyboardEvent 를 dispatch 하여 위 표의 모든
   항목이 동작함을 스스로 확인하고, 확인 방법과 결과를 VERIFICATION 또는
   README 에 남길 것.
