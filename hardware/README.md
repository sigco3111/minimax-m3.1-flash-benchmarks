# REC-1 — desk recording controller

A small USB controller for creators who record with OBS Studio: one button
starts and stops the recording, a red LED shows that the recording is really
running, a small OLED shows the recording time, the current scene and the
state of the connection, and a second button switches the scene.

The device is a **desk accessory**: USB power only, no battery, no radio, no
mains input. It is built from an off-the-shelf MCU board (Adafruit QT Py
RP2040) and a 3D printed case.

```
┌─────────────────────────────┐        USB-C (power + CDC)        ┌──────────────┐
│ REC-1                       │◀───────────────────────────────▶│ OBS Studio   │
│  REC button  ──► CMD REC …  │        line protocol            │ (obs-websocket 5.x)
│  SCENE button ─► CMD SCENE… │                                  └──────────────┘
│  red LED   ◄── ST REC 1     │  ← the LED follows the *real* OBS state
│  OLED       ◄── ST TIME/LINK│
└─────────────────────────────┘
```

**Status: design complete, digitally verified, not yet built.** No physical
device exists yet — everything that needs real hardware is listed in
`VERIFICATION.md` §5.

## 3. Build the hardware

### 3.1 Print the case

```bash
cd enclosure
./build.sh          # OPENSCAD=/path/to/OpenSCAD if it is not in PATH
```

Print `rec1_bottom.stl` and `rec1_top.stl` (PLA/PETG, 0.16 mm layer, 3
perimeters, 20 % infill, no supports). Print the face panel upside down.

### 3.2 Wire it

Follow `WIRING.md`:

1. Plug the OLED into the STEMMA QT port of the QT Py with the 100 mm cable.
2. Screw the OLED onto the four printed posts (M2.5 screws + nuts).
3. Drop the QT Py into the printed cradle.
4. Push the two switches and the LED into the face panel, wire them with
   22 AWG to the castellated pads A2, A3, A1 and GND, and solder the 220 Ω
   resistor in line with the LED.
5. Drop the four M3 nuts into the boss pockets of the bottom shell, place the
   face panel on the bosses and tighten the four M3 screws.

### 3.3 Flash the firmware

```bash
cd firmware
./setup.sh          # once: arduino-cli + core rp2040:rp2040@6.4.0 + 3 libraries
./build.sh          # -> firmware/build/rec_controller.ino.uf2
```

Flash the UF2: hold `BOOTSEL`, plug in USB-C, release `BOOTSEL`, copy
`rec_controller.ino.uf2` onto the `RPI-RP2` volume.

### 3.4 Run the bridge

```bash
python3 host/bridge.py --list-ports
export OBS_WS_PASSWORD='…'          # only if obs-websocket authentication is on
python3 host/bridge.py --port /dev/tty.usbmodem14101 \
                       --scenes "Intro,Gameplay,Outro"
```

In OBS: *Tools → WebSocket Server Settings → Enable WebSocket server* (port
4455).

### 3.5 Look at the design

```bash
open preview/index.html      # or: python3 -m http.server 8000
```

## 4. How the device behaves

| Situation | Screen | Red LED |
|-----------|--------|---------|
| Idle, everything connected | `READY`, `LINK:UP OBS:UP`, scene name | off |
| Recording | `RECORDING`, running timer | **on** |
| Button pressed, OBS has not confirmed yet | `WAITING FOR OBS...` | off |
| USB cable unplugged / bridge stopped | `LINK:DOWN`, `HOST LINK LOST` | off |
| OBS or the bridge cannot reach OBS | `OBS:DOWN`, `OBS NOT CONNECTED` | off |
| OBS is recording but the bridge is gone | unknown → LED off, `HOST LINK LOST` | off |

The LED is driven by `ST REC 1`, i.e. by the state the host read from OBS —
never by the button press. If the state is unknown, the LED stays dark.

## 6. Honest limitations

* **Nothing has been built.** The firmware was never flashed, the OLED was
  never driven, the buttons were never pressed and no current was measured.
  The power budget is calculated from published data, not measured.
* **No PCB.** The prototype uses castellated pads and short wires. A PCB is
  the production step; no layout, no DRC, no fabrication data are delivered,
  so nothing here is "manufacturing ready".
* **The CAD is verified against its own dimension table**, not against
  measured parts. Four manufacturer values are assumptions (listed in
  `enclosure/README.md`).
* **The obs-websocket client implements the subset of protocol 5 that this
  device needs** (Hello/Identify, requests, events). It was tested against
  the mock server in `host/mock_obs.py`, not against a real OBS instance.
* Stock and prices in `BOM.csv` were observed on 2026-11-19 and change.
